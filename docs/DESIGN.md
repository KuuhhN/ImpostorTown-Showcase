# 设计与实现笔记

## 一个能被体验的闭环

玩家进入小镇的理由是车辆故障。维修目标把空间探索、道具获取和操作反馈连接起来：信息与钥匙决定去哪里，有限物资决定拿什么，维修状态决定什么时候能离开。怪物与昼夜变化在同一空间里改变探索压力。

## 从“按一下修好”到可读的操作

车辆拆为轮胎、电池、点火线圈和传动皮带等子系统。通过部位选择、工具要求、拆装前置条件和最终检查让玩家理解进度。八孔轮胎需要保持视觉孔位与交互状态一致；电池端子、线圈和皮带分别提供局部观察与操作反馈。

这项设计的价值是将抽象任务变成可观察状态。玩家应当知道当前操作对象、需要的工具和下一步，而不是反复尝试无反馈的点击。

## 遭遇与节奏

维尔的遭遇按窥视、接近和攻击展开，用路灯与距离变化提供预警。角色 B 提供对话与人物存在感。昼间街道建立方位认知，夜间相同地点依靠灯光、轮廓与手电重新组织可见信息。

## 迭代方式

先定义期望体验与边界，再让 AI 协作生成实现或素材；在运行中比较效果，记录故障条件，修改并回归关键流程。美术选择同时看单张效果和游戏里的尺寸、透明边缘、朝向与光照表现。

## 当前范围

已交付 Windows 可玩 Demo 和探索—修车—离镇闭环。美术集中展示的 B 双面素材不等于已实现 SAN 驱动切换；实时大模型 NPC、多结局及完整商业内容不作为当前成果。后续优先扩大人工试玩样本，改进引导与节奏，再考虑扩展功能。
